# Roadmap

## Completed foundation

- Cycle 1: separate repository, Gen-1 gateway, persistent Goal/Plan/TaskRun, bounded execution, verification, restart recovery.
- Cycle 2: provider-neutral model planner boundary, structured PlanProposal, deterministic validation, persistent permission/risk/approval/criteria/provenance, approval restart reconciliation, planner recovery, independent goal evaluation, security acceptance.
- Cycle 3: personal context selection, persistent sessions, bounded background task control, restart recovery, and relevance-filtered proactive events.
- Later software cycles: typed connectors/tools, persistent world model, cross-domain verified completion, approval-safe engineering orchestration, multimodal/voice/device/robot safety harnesses, experiments, audit, rollback, diagnostics, daily OS and controlled self-improvement.

## External acceptance blocker

The protected provider credentials required by the currently accepted routes resolve on the current host. Reasoning/planning/coding/tool-use, multimodal, embedding, reranking, image generation and safety remain on their verified NVIDIA routes with fallback disabled; Google Gemini 3.8 Live is the accepted production voice route. NVIDIA VoiceChat remains separately registered and provider-specifically blocked on authorization-safe function delegation. Provider/device-dependent capabilities are accepted only from real evidence, never from mocks.

## Remaining master-spec software boundaries

The capability matrix is supporting evidence, not the complete product specification. Gen-2 now integrates bounded specialist delegation and first-class automation creation/control over the reliable Gen-1 automation store plus Gen-2 background continuation. The dedicated document-intelligence pipeline is now integrated locally with structured extraction, provenance, bounded retrieval, and PersonalAgent context. The generalized robotics-perception software boundary is now integrated and simulation-live verified; physical sensors/robots remain externally blocked. `workspace_test` is now live accepted through the Gen-2 strict local Bubblewrap profile `SPARKLE-GEN2-WORKSPACE-STRICT/1`. The model-visible schema exposes only `project_name`; exact persisted human approval produces a one-use owner/goal/task/step/workspace-scoped Gen-2 execution grant which is consumed before Gen-2 injects Gen-1's transport approval flag. A bounded validated source bundle is copied into an ephemeral worker workspace; the namespace root and runtime are read-only and only `/workspace` is writable, networking/PID/user namespaces are isolated, environment and credential access are stripped, deterministic resource/output/source-size bounds apply, and completion requires strict hostile-canary health plus independent run-history reread. Worker identity rotates across restart and stale execution handles are not reusable. The pre-existing TLS worker remains diagnostic-only and is not a `workspace_test` fallback; the non-isolated local runner remains unacceptable.

## Terminal classification

`default_acceptance.py` classifies its declared capability set, but does not supersede the master specification. Account/provider/device-dependent surfaces remain externally blocked until genuine acceptance; production deployment remains deferred pending target selection.

The first-class Daily Operating System boundary is now integrated: bounded Personal Context becomes a persistent provenance-bearing daily brief with restart/idempotency, approved disposition changes, and unresolved carry-forward.

### Adaptive learning closure

The original learning loop is now represented as persistent Gen-2 software: explicit goal/objective and approved bounded curriculum, verified Gen-1 progress evidence when available, approved assessments, deterministic weakness detection, retraining recommendations, completion only when every unit reaches the mastery threshold, owner isolation, idempotency and restart recovery. External teaching/content providers are not required for this state model and no model output can self-assert mastery.
