# Voice

Gen-2 now has a typed streaming voice-session boundary over the existing PersonalAgent rather than a separate voice agent. `VoiceSessionService` accepts bounded 16-bit PCM, 16 kHz mono input frames, records transcript/provider/session provenance without persisting raw microphone audio by default, sends final user transcripts through the existing `ConversationService -> PersonalAgent` goal/plan/permission/risk/approval/execute/verify path, and only then permits provider speech rendering of the verified human-readable SPARKLE response. Provider output audio is validated as 16-bit PCM, 22.05 kHz mono.

The production model registry contains `nvidia/nemotron-voicechat` as the semantic `voice` route with audio/text inputs, text/audio outputs, streaming support, the configured NVCF function/version identifiers, `NEMOTRON_VOICECHAT_API_KEY` as a secret reference, and `allow_fallback=false`. The provider is not treated as inference-ready from metadata or `/v1/realtime/health` alone. NVIDIA Cloud Functions streaming requires an intermediary/proxy that authenticates/authorizes clients and supplies NVCF routing/authentication headers. No verified intermediary/protocol endpoint is configured in Gen-2, and this runtime does not currently resolve the VoiceChat secret reference, so the production voice route remains `UNAVAILABLE` and no endpoint is guessed.

Voice lifecycle states are `CREATED`, `CONNECTING`, `CONNECTED`, `ACTIVE`, `STOPPING`, `COMPLETED`, `FAILED`, `UNAVAILABLE`, and `CANCELLED`. Active provider streams are not claimed resumable across process restart; persisted sessions recover to `UNAVAILABLE` with an explicit transport-session limitation. Interruption/cancellation is bounded and a provider error or malformed transcript/audio event never becomes successful completion. SENSITIVE, HIGHLY_SENSITIVE, and DEVICE_CONTROL voice sessions are blocked from external transmission by default.

The legacy injected STT/TTS `VoiceRuntime` remains only for backwards-compatible software lifecycle tests; it is not production VoiceChat and is never used as a fallback. Notification voice delivery remains unavailable until a real provider speech-to-speech session has been accepted.
